# 代码注释规范

本规范适用于 `packages/` 与 `apps/` 下的全部源码；`packages/ui` 随上游 `@violet/ui` 同步，不在本仓单独维护。

## 语言

- 注释用中文；专有名词（MCP、CSP、WebSocket、Durable Objects、Bridge）保留原文。
- 过期的注释比没有更危险：代码行为变化时同步更新或删除旧注释。
- 注释行宽不超过 100 列（与 Biome `lineWidth` 一致，Biome 不会折行注释）。

## 写什么

注释说明调用方从名字、类型和签名看不出的契约：零值含义、业务不变量、安全边界、失败方式、必须释放的资源。

判定标准：**删掉后调用方损失信息吗？不损失即删。**

注释必须能由代码或测试验证。写下一个不变量前，先找到强制它的位置；无法确认的不写，去查测试或 `docs/design/architecture.md`。

## TSDoc 形态

导出的函数、类、类型、常量、组件和 hook 用 TSDoc 写在符号上方，让它进入 hover 与 `.d.ts`：

```ts
/**
 * 按键串行化的异步互斥锁：同一 key 的任务严格先后执行，不同 key 互不阻塞。
 *
 * @param key - 串行化的作用域，通常是 artifactId。
 * @returns fn 的结果；fn 抛错时锁照常释放。
 */
export class KeyedAsyncLock { … }
```

一句话能说清的用单行：

```ts
/** 结果文案的默认展示时长。 */
const DONE_DURATION = 1600
```

标签约定：

- `@param` / `@returns`：只写签名外的信息（取值约束、单位、前置状态）。自解释的参数不写；写了就必须有签名外的信息。
- `@remarks`：首行装不下的次要语义，如消费场景、副作用、缓存行为。
- `@default`：默认值的语义，不写「默认 false」这种复读。
- `@throws`：会抛出或拒绝的错误及其条件。
- `@typeParam` / `@example`：泛型的语义；示例必须可运行。
- 状态转换直接写箭头：`drafting → submitted → closed`。
- 引用其他符号用反引号 `` `Name` ``，不用 `{@link}`。

## 字段注释规则

| 字段归属                                                                                                    | 什么时候写注释                                                                                                                                     |
| ----------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/protocol` 的领域模型（`primitives.ts`、`domain.ts`、`artboard.ts`）；`packages/server/src/domain` | 每个命名字段必注，写在字段上方。写单位或格式、枚举语义、引用关系、可选与缺省的含义；容易混淆时写明不变量或与相邻字段的区别。改到这些文件时也补齐。 |
| 协议的输入输出与消息载荷（`mcp.ts`、`http.ts`、`realtime.ts`、`bridge.ts`、`storage.ts`）                   | 只补名字和类型没说清的语义：零值含义、何时必填、互斥关系、计算口径。                                                                               |
| 应用层用例的参数与返回、持久化行结构、容器装配参数                                                          | 不逐字段复述名字与类型。只注释事务边界、并发约定和存储格式约定。                                                                                   |

- 紧跟 schema 的 `z.infer` 类型别名不重复说明。
- 需要随 JSON Schema 导出给 Agent 或其他语言客户端的字段说明用 `.describe()`；它与 TSDoc 二选一，不重复写。

## 头注释禁写

- **动机叙述**：「本 hook 消除了 7 个页面的重复样板」属于 PR 描述。
- **历史论证**：「原来有竞态，已拆成 X」属于 commit 或 `docs/adr/`。
- **被否决的方案**：要写就压缩成一句「为什么不用 X」。
- **复读签名**：翻译参数名、返回类型，或写「调用 GET /api/v1/…」。
- **步骤标签**：给短函数标「第一步、第二步」。

设计论证放 commit body 或 `docs/adr/`，不进源码。

## 行内注释

头注释让位给行内注释的部分：

- **魔法值理由**：值旁一句为什么是这个数，写在行尾或行上。
- **行内陷阱**：函数体内非显然的坑，比如为什么要解构某个引用、为什么要绕开某个 API。
- **编排契约**：签名看不出的数据流顺序，如「读配置 → 回填 → 只提交部分字段」，一行。

私有函数默认不注释，非显然时一句。函数体内的说明用 `//`；写在导出符号上方的 `//` 说明应改成 TSDoc。

## 默认不写头注释

- **天然自解释的函数**：函数名是操作，参数类型是请求，返回类型是响应，下一行代码就是协议与路径。API client、查询 hook、MCP 工具到 HTTP 的映射都属于此类。只补签名外的语义，且不带函数名前缀。
- **只做 re-export 的 `index.ts`**。
- **测试**：用例名自解释。只在桩、时序控制和安全用例的非显然前提旁写一句。
- **CSS**：只写 token 取值理由和布局陷阱。

## 组件与 hook

- props 不超过 3 个且都是原始类型时可以内联；超过 3 个、含回调或带泛型时抽 `XxxProps` interface，在 interface 上写字段注释，组件函数头只写职责，不再堆 props 说明。
- hook 的头注释写编排契约：依赖哪些输入、何时触发、返回值各自的语义。

## 正反例

```ts
// ✅ 契约：签名看不出的失败方式与原子性
/** 按顺序应用增量替换；任一条匹配失败则整体不生效，source 保持原样。 */
export function applyTextEdits(source: string, edits: readonly TextEdit[]): string

// ❌ 复读签名
/** 应用文本编辑，参数为源码字符串和编辑数组，返回字符串。 */

// ✅ 签名外的语义
/**
 * 请求 Daemon 停止。
 *
 * @remarks 服务端收到请求后才退出进程，响应总是先送达；确认已退出须再查 daemon/status。
 */
export async function stopDaemon(): Promise<{ ok: true; status: 'stopping' }>

// ❌ 带函数名前缀并复述路径
/** stopDaemon - 调 POST /api/v1/daemon/shutdown 停止守护进程。 */
```

# Web 文案与实现规范

## 文案

- 面向用户的术语见 [CONTEXT.md](../../CONTEXT.md)。一个对象在入口、详情、失败提示和读屏名称里用同一个名字。
- 按钮写动作。上下文已经给出对象就只写动词，例如「发送」「保存」「打开」「重试」。只有需要区分目标才补对象，例如「导出画板」「导出作品」。
- 正常状态交给标题、选中态和控件表达。请求中用共享控件的 `loading` 或骨架；空、失败、无权限分别写当前状态，必要时给一个可执行的下一步。
- 保留会改变决定的信息：授权对象、固定版本、删除范围、未保存的改动、导出后果。技术诊断不要写成对话框的常驻说明；可执行的 CLI 命令原样显示。
- 对照 Claude Artifacts 时核对动作和范围。中文按 Akasha 用语，不把内部翻译写成 Claude 的官方译名；不翻译用户作品、代码、文件名或标识。

## 组件与样式

- 页面负责布局和业务流程。按 Violet 的组件复用原则，以 `@akasha/ui` 的外观、交互和 API 为准。已有 `Button`、`Field`、`Input`、`Textarea`、`Select`、`Checkbox`、`Slider`、`Skeleton` 等控件，直接使用。标题、链接、表格和画布绘制用合适的语义元素；导出的独立 HTML 不依赖工作台组件库。
- 忙碌状态用 `Button.loading`，按钮文字保持稳定。表单标签、错误和帮助用 `Field` 接线。控件缺能力时先定最小共用扩展，再接入业务；不在业务页复制样式或另造同类控件。
- 使用语义颜色和 Tailwind 标准间距、逻辑方向。工作台用黑白灰；成功、警告和错误才用状态色。作品样式保持独立。可聚焦元素留足描边空间，避免被滚动容器裁掉。
- Tailwind v4 用当前主题的 canonical 类名：`p-[12px]` 写 `p-3`，`max-w-[200px]` 写 `max-w-50`，逻辑方位用 `inset-s-*` / `inset-e-*`，`!important` 写后缀。任意值只用于主题无法表达的尺寸或计算，不借改动扫全库。
- 复合控件先定状态所有者，以及 `ref`、`className`、事件取消和焦点落点。通用组件保留原生或行为组件语义；路由、请求、业务校验和文案由消费方拥有。
- 修改 `packages/ui` 的公开组件时，样式、类型和 `package.json` 导出同步。分别验证包内行为和真实页面接线；发布入口或打包变更还需在工作区外安装实际 tarball 验证，不用 workspace alias 代替。

## React 与模块

- 顶层 React 组件用函数声明导出；组件、hook 和普通函数体内的辅助函数用命名箭头，按依赖先后定义。简单的参数转发可内联，纯计算显式传参放组件外。只有真正需要稳定引用时才用 `useCallback`。
- 先算业务条件，再用提前返回或互斥条件直接渲染。不要套三元（Web 源码由 Biome 检查），也不要用可变 JSX 临时变量代替条件分支。
- 先找功能归属，再选目录。widget 组合已有功能；路由能独立打开的导出、分享等用例归 feature，从对应切片的根入口使用，不经过 widget 转出。完整依赖方向见[外壳分层](../design/architecture.md#123-外壳分层)。
- 同一职责的展示组件可在 `ui/` 平铺；订阅和交互编排进 `hooks/`，持有状态的数据结构进 `model/`，纯计算与转换进 `lib/`，业务请求进 `api/`。像工具栏、检查器这样共同变化的多文件交互可以单独成组。文案跟随消费它的功能；没有对应职责就不创建目录。
- 协议和存储标识留在领域层。重构时保持权限、选区、固定版本、草稿和焦点契约。验证真实操作路径，不靠匹配源码或旧说明文案作为验收。
- 写新组件、hook 或工具前先查 `@akasha/ui`、本切片和已有公共层。只服务一个切片就留在切片内，第二个真实消费方出现才上提。只有多文件复合体需要子目录，不预建空分层。
- 有多个字段、回调或泛型的组件接口用命名 `XxxProps`。对外类型必须反映实际 DOM 和可观察状态；保持单一状态源，不用不安全断言把摘要伪装成正文。
- 请求的加载、成功为空、失败、无权限分别处理。DTO 如实区分 `null` 与未提供；`0`、`false` 和空字符串合法时用 `??`，不以默认值遮住错误。不把 API 数据复制到第二个状态源。

## HTTP 请求

- JSON 请求统一使用 `@/shared/api/request`。传输层只做地址、Cookie、取消与协议错误解析；不重试写请求，不因 `401` 自动切换登录状态。业务端点在所属切片的 `api/`；Hub 登录会话明确走工作台同源，不跟随作品 API 地址。文件、探测和 WebSocket 不经过 JSON 封装。
- 在端点函数上写调用方需要的契约，例如受理与完成的区别、固定版本、并发冲突和提交副作用。不要逐行复述 HTTP 方法、路径或签名。

## 页面验收

- 输入工具先定义点击、拖动、滚动、修饰键和 Esc 各自的作用，同一模式只保留一个入口。短暂加载及局部失败不能夺走画布输入或清除正在编辑的草稿。
- 改动滚动区、折叠区、弹层或工具栏，在实际消费页用 Tab 和指针操作；检查窄屏、工具切换、焦点环四边和关闭后的焦点恢复。项目自有动画尊重减弱动态。DOM 测试不能替代真实布局、跨域 iframe 或指针验证。

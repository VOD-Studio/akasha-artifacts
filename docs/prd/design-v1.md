## 为谁解决什么问题

- **产品负责人**已有截图、品牌资料和代码库，要在同一页比较几种可辨认的方案，而不是拿着一张预览反复给 Agent 描述位置。
- **设计师**要能直接改文字、布局或作品定义的参数，看见真正会动的画面，按需试玩；不能每次改颜色都重新生成一稿。
- **评审人与协作者**要分得清“给同事留言”和“请 Agent 修改”，共同编辑同一份设计，又能证明交付的是哪一版。
- **工程师与交付方**需要真实组件、源码与固定版本，或一个能在目的工具继续工作的成品，而非截图、空白外链或作者的登录凭据。

**首版成败场景**：用团队的真实按钮、字号和一张参考图生成两个结账方案；在同页修改并比较，邀请另一人共同编辑；针对错误态在原线程得到 Agent 改稿；把选定版本交给工程师，并在指定目标打开。任何一步只能靠口述、截屏或手工重建，相关需求就未完成。

## 首版能力矩阵

“基础”指 `v0.4.1` 的文档或已关闭实施票，不是本次重新跑过；“缺口”含需补做或重验的地方。**D01–D16 都是首版**；有条件能力用对应角色、连接、输入或画板验收，不因当前账号没有权限而删除。

## 验收与发布决定

1. **固定样本**：用自己可公开的材料，不取用户私稿。包括单静态板、两页多板、同页静态／动效／交互混排、含真实组件的设计、长文打印、100／1000 板及完全重叠的布局。保留主线既有 HTML、React 和工程模板测试，不要求旧制品迁移成 Design 才能打开。
2. **同一份设计贯穿验收**：记录版本、角色、前置条件、结果链接或导出文件。作者创建和直改，另一位编辑者并发修改，评论者只评审，查看者只检查／试玩，撤权者重新打开失败；普通定位链接不替代授权。固定版本不随重命名、挪板或头版本推进而漂移。
3. **视域预算是发布目标，不是跑分**：每版本每页索引世界坐标包围盒，视口加缓冲挑候选；远处只绘轮廓、近处按需上真实缩略，树按可见行加载。密集重叠允许最坏 O(n) 查询但不挂 n 个运行实例。1440×900、60 Hz 的同一 Tern 环境，100 和 1000 板分别连续平移缩放 10 秒，记录冷／热缓存、长任务及 p95（目标 ≤24 ms，不声称锁 60 fps）；鸟瞰 0 个活跃画板，近景至多 24 个高细节预览，其中至多 6 个轻量动效，整区至多 1 个交互沙盒。切后台、减少动态和暂停优先于播放预算。
4. **发布判定**：上述每行都有负责人可领取的 issue 或已交付基线；每个外部目标有自己的正／反例；用功能结果而非面板数量、截图或关单数判定。已确认的 Design 能力缺失、越权、数据丢失、历史被覆盖或规模指标未过，都不能标“已对齐”。若只能发预览版，列出未过项，不缩小分母。更新竞品基线时记录日期、来源与影响到的 D 编号。

## Design 首版之后

| 阶段 | 产品与用户任务 | 如何判断不是给 Design 多加一个按钮 |
| --- | --- | --- |
| **二：其他 Artifacts** | 先做 Docs 的选段协作／修订和可编辑文档交付、Slides 的逐页编辑／放映；再做 Data 的可查来源与刷新、Sheets 的跨表公式；再做 Whiteboards 的多人自由整理、Motion 的时间轴及 MP4。通用交互制品补按当前使用者授权的 Agent 能力、连接器、文件及个人／共享存储。 | 每一类有独立创作对象、保存／分享语义与一份可重新打开的真实输出。先复用 `document`、`data-story`、运行存储等基础；它们存在不等于有完整编辑器。Design 导出 PPTX 在首版，**Slides 编辑器**在此；Design 板内动效在首版，**Motion 视频创作**在此。 |
| **三：向 Figma Design 扩展** | 先做可编辑容器与 Auto Layout（横纵／网格、重排、尺寸随内容）；再做主组件／实例覆盖／Variants、跨文件库与更新、变量集合／别名／Modes；再做矢量节点／布尔运算、可视化连线／条件／转场、Dev Mode 式规格、可开发标记、变更比较与代码映射。 | 把按钮文案换成长译文，容器能重排；只覆盖实例文字仍能接受组件更新；切主题不复制整板；可从开发标记定位准确版本和实现。首版“使用既有品牌组件”不冒充组件库编辑器，“交给 Agent”也不冒充 Dev Mode。 |

两条后续路线都在 Design 首版之后。优先拓展其他 Artifacts，不要求所有其他编辑器写完才研究专业布局。项目自有的 Verify、PR 走查、状态时间线等继续工作；不把它们改成画板。Figma 是能力参照，不承诺 `.fig` 无损往返、插件市场、FigJam、Figma Sites 或复制整个商业套件。

不仿制 Claude 的套餐计费、账号体系、旧独立站迁移或原生客户端壳；**不因此省略**角色权限、协作、触屏工作流或真实外部交付。来源／凭据不足是明确的发布风险，不是把已知首版功能移到后续的理由。
